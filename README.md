# 知行合一AI实验室

一个用 AI（Claude Code）从零搭建的个人 AI 应用实验室。目前跑在里面的第一个功能是书影/生活追踪：记录看过的书、剧，以及日常动态（股票关注、运动、照片、想法）。数据全部存在本地/私有存储，不跟踪。原名"书影追踪"。

![首页](static/changelog/homepage.png)

## 功能

- **书影管理**：添加书/剧，记录每日进度、用时、感想；条目状态（想看/进行中/已完成/放弃）可以在首页直接切换
- **豆瓣自动导入**：粘贴豆瓣链接自动填充标题、封面、作者/页数或集数
- **动态记录**：股票关注、运动、照片（本地上传）、日常想法，每条都能写评论
- **统一时间线**：首页把书影进度更新和动态按日期合并成一条瀑布流，未看完的书剧每次更新都会重新出现在当天，滚动到底自动加载更多
- **全站搜索**：搜书名、作者、总评、每日感想、动态内容
- **打卡热力图**：GitHub 风格的每日活动热力图
- **AI 截图识别导入**：上传朋友圈截图，用 Claude 视觉模型自动识别文字、判断类型、草拟内容，确认后批量保存
- **一键分享图**：单条目 / 按天，生成适合发小红书的图片卡片（瀑布流排版）
- **更新日志**：网站自带 `/changelog` 页面，记录开发过程，还有代码量热力图（见下方"更新日志"）
- **性能指标**：登录后可看 `/admin/metrics`，实时 QPS / 延迟分位数 / 按接口拆分统计，更新日志页也有一个精简的公开摘要
- **小说**：`/novels`，写小说、按章节管理，章节还能归到有名字的卷里，配人物角色概念图和 AI 生成的视频（支持直接上传或粘贴 B 站/YouTube 链接），章节里可以挑选出场人物/视频、参考书目从已有书影里选，还有一键分享图，也能整本导出成 Word / PDF（导出会带卷标题），章节页还能用浏览器自带的语音朗读；小说和单个章节都可以单独上锁，锁定后未登录看不了；这部分内容默认不需要登录也能看，创作、导出、朗读和被锁定的内容都需要登录
- **多账号系统 + 持久化存储**：账号登录（不再是共享密码），每个账号的书影/动态/小说数据互相隔离；管理员能在 `/admin/users` 后台加账号、开关自助注册、下载全站数据的完整备份 zip、帮账号重置密码（直接改或发一次性重置链接）
- **中英双语**：导航栏有 中文/EN 切换，点一次全站记住；从公开首页到日常记录到小说创作到后台管理，界面文字全部支持中英切换。只翻界面文字，自己写的书影感想/动态/小说正文永远保持原文，不会被机器翻译
- **交易盈亏**：`/trading`，上传 Schwab 导出的交易记录 CSV，按 FIFO 把开仓/平仓自动配对算出每日已实现盈亏，生成盈亏日历（周一到周五，绿涨红跌）和累计盈亏走势图（可一键生成分享图，分享图不显示具体金额，只看走势形状，以及按天、按笔两种算法的胜率和盈亏比，还可以勾选可选项带上目前持仓——只显示品种和建仓日期，不显示数量和成本），统计里能看到毛利润/手续费/净利润的拆分，以及「按天统计」（盈利天数/亏损天数/胜率/盈亏比）和「按笔统计」（总交易笔数/盈利笔数/亏损笔数/胜率/盈亏比，按每笔平仓算）两套并排的胜率盈亏比——两种算法经常对不上，都保留展示，以及按品种拆分的盈亏表格（每个品种的笔数、盈利笔数、亏损笔数、总盈利、总亏损、净盈亏，按净盈亏绝对值排序；期权按标的合并，同一个 QQQ 不管哪个到期日/行权价/看涨看跌都算一行，FIFO 配对本身仍按精确合约区分），以及「目前仍持有的仓位」表格（品种、数量、平均成本、成本合计、建仓日期，期权保留精确合约字符串不合并，多笔建仓/部分平仓按剩余数量加权平均成本，只是成本不是当前市值，没接实时行情）；可以陆续上传新导出的文件追加历史，重复的交易会自动跳过；需要登录
- **消费追踪**：`/expenses`，上传工商银行「历史明细」PDF（带密码），生成消费日历（周日到周六，只统计银行标为「消费」的实际购物记录，不含转账/理财）、按摘要分类做支出小计、按对方户名统计的消费商户 Top 10（年度 + 每月各一份）、年度消费汇总（按月柱状图 + 12 个月方格，可切换年份，可一键生成分享图——分享图不显示具体金额，只看每月消费高低走势）；同样支持陆续追加、自动去重；需要登录
- **功能一览**：`/showcase`，介绍交易盈亏/消费追踪/小说创作/分享动态四大功能的展示页，渐变光晕背景、卡片浮现动画，每张卡片还有一个纯 CSS/SVG 的小演示动画（走势线自己画出来、柱状图红绿交替生长、文字逐渐浮现、动态卡片依次淡入），一句话+跳转链接，一键生成海报风格的分享图（标题+编号列表+水印）；需要登录。同一组功能卡片也放在了公开首页（没登录能看到那个），在「网站的技术架构」图上面
- **路线**：`/routes`，在一张真实地图（自建 Leaflet.js + OpenStreetMap 瓦片，本地打包，不用申请 API key）上依次点几下手绘一条路线，也可以直接输入地点名称（一行一个，比如东京/京都/大阪，20 个都行），用 OpenStreetMap 自己的免费 Nominatim 地名查询自动按顺序查坐标连线（遵守它一次一个请求的规则，每次查询间隔 1.1 秒，页面有进度提示；查不到的地名会被跳过并汇总告知，不卡住整批），两种加点方式可以混用，每个有名字的点鼠标悬停能看到地名；地图右上角能切换「标准地图」（OSM 街道图）和「地形图」（OpenTopoMap，带等高线/地势晕渲，同样不用申请 key）；配标题和国家/地区标签（中国/日本/美国/其他，只是标签，地图本身全球可用），保存后默认私密，点「公开分享」生成一个免登录访问的链接，也能一键生成分享图（标准/地形/路线轮廓三种样式可选，前两种是把真实的 OSM/OpenTopoMap 地图瓦片拼出来、路线画在上面并带地图版权信息，用 `staticmap` 库；路线轮廓不要真实地图背景，米色底、彩色圆点标记，只用简单投影把各点连线、标上城市名，不用下载瓦片所以更快更小）；单条路线最多 2000 个点，格式不对的点会被过滤掉不会拖累整条路线保存失败；需要登录才能画/管理，公开的路线任何人都能看
- **PWA**：可以在手机浏览器里"添加到主屏幕"，像 App 一样用

## 技术栈

Flask + SQLite，服务端渲染（Jinja 模板 + 手写 CSS，没有前端构建流程）。Pillow 用来生成分享卡片图片。豆瓣抓取用 `requests` + `BeautifulSoup`。AI 截图识别接的是 Anthropic 的 Claude API。银行流水 PDF 解析用 `pdfplumber`（含密码解密、按字符渲染属性过滤防伪水印）。地图画路线用 `Leaflet.js`（本地打包）+ OpenStreetMap 瓦片，真实地图分享图用 `staticmap`（纯 Python，基于 Pillow）。

## 本地运行

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./run.sh
```

打开 http://127.0.0.1:5050 即可。首次启动会自动建好本地 SQLite 数据库。

可选功能需要配置 `.env`（参考 `.env.example`）：

- `ANTHROPIC_API_KEY`：开启「AI 截图识别导入」
- `APP_PASSWORD` / `SECRET_KEY`：部署到公网时开启密码登录

## 部署

用 `Dockerfile` 构建，部署在 [Railway](https://railway.app) 上（网页操作为主，从 GitHub 仓库直接连自动部署）。持久化数据存在挂载到 `/data` 的卷里，`APP_PASSWORD` / `SECRET_KEY` 通过环境变量配置。

（此前也评估过 Fly.io，配置文件 `fly.toml` 还留着，但新账号触发了风控验证，改走了更省事的 Railway。）
